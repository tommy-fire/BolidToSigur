# BolidToSigur · v3.1

**Привычный порядок сохранён:** логин + пароль → автоматический поиск базы → выгрузка сотрудников, ключей и фото. Восстановления из `.bak` больше нет.

## Начать здесь

1. **[Перенос сотрудников и W34](01_ПЕРЕНОС.md)** — запуск, автопоиск, сверка, импорт.
2. **[Подключение E510 в вагончике](02_ПОДКЛЮЧЕНИЕ.md)** — порядок монтажа и проверки безопасности.

Запуск Windows: **`ИНСТРУКЦИЯ/START_SAFE.bat`**. Старые запускатели миграции и прямой выгрузки также открывают новое окно. Python 3.10+, Tkinter, ODBC-драйвер Microsoft SQL Server. Python-зависимости в `ИНСТРУКЦИЯ/requirements-safe.txt`.

## Что входит

- Рабочие программы в `ИНСТРУКЦИЯ/`: автопоиск/SQL (`bolid_db.py`), строгий контроль ключей (`safe_w34.py`), фото и кадровые поля (`migration_data.py`), графический интерфейс.
- `research/` — официальные руководства Sigur и источники исследования.
- `audit/` — исходный аудит и воспроизводимые офлайн-тесты.

Старые монтажные TXT, PNG, собственный PDF, HTML, SVG, сборщики схем и утилита `.bak` удалены из рабочей версии как устаревшие/ошибочные. Оригиналы остаются в истории Git, коммит `2be85ab`. Не использовать их для подключения.

## Границы переноса

Согласованный набор: ФИО, табельный номер, компания/отдел, должность, фото, дата рождения, паспорт/прописка, проверенные W34 и обе границы срока карты с точным временем. Телефоны, email и произвольные дополнительные колонки не входят в целевой XLS; исходные данные сохраняются.

Дата рождения/паспорт/прописка — в отдельные дополнительные поля либо переключателем в три первые строки примечания. Поддерживаются подписанные строки исходных примечаний; неизвестный формат и конфликты требуют сверки.

Начало и окончание карты — из **двух явно выбранных полей**. Никакого округления времени или автоматической трактовки статусов. Несколько карт со сроками по умолчанию исключаются до отдельной проверки: документация неоднозначно описывает строки продолжения; для пустой базы предусмотрен диагностический XLS.

Согласовано: **Турникет — 24/7**, вход и выход, все дни. Этот режим назначается в Sigur отдельно после сверки; комнату охраны не включать.

CodeP декодируется только для поддерживаемого профиля: 08, FE01/FE02, 8 байт, семейство 01, CRC8/MAXIM. Автоматическое применение номера требует контрольных пар. Неизвестные форматы не обрезаются наугад. Три совпадения не доказывают универсальность для смешанной базы. См. `research/ИСТОЧНИКИ.md`.

**Проверено офлайн, не проверено на вашем SQL Server, Windows GUI и Sigur.** Сначала 3–10 человек в пустой тестовой базе, потом массовая миграция. Оставить рабочий аварийный выход свободным до приёмки монтажником.

```bash
python -m unittest discover -s audit -p 'test_*.py' -v
```
