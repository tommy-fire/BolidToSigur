# BolidToSigur · v1.0.0

**Две кнопки: Болид → файл `.bolid` → полный пробный XLS для Sigur.**

1. Распаковать лёгкий ZIP в `C:\BolidToSigur`, открыть `ЗАПУСК.bat`.
2. Ввести логин/пароль → «1. Найти базу и выгрузить». Автопоиск сохранён, `.bak` не используется.
3. «2. Выбрать выгрузку и создать файл Sigur» → выбрать `.bolid`. SQL повторно не нужен.
4. Открыть `ПРОБНЫЙ_ПОЛНЫЙ_Импорт_Sigur.xls` из новой папки результата.

Если `.bolid` уже есть, после обновления достаточно кнопки 2. [Практическая инструкция и сопоставление колонок](01_ПЕРЕНОС.md).

## v1.0.0 — первая стабильная версия

**Проверено на реальной системе: сотрудники, карты W34 и сроки перенесены, система работает (подтверждено владельцем).**

- **Примечание — только `Дата рождения: ДД.ММ.ГГГГ`**, или пусто, если достоверной даты нет. Никаких паспортов, прописки, исходных заметок или служебных предупреждений в примечании. Это правило действует во всех XLS-режимах.
- Паспорт и прописка остались отдельными колонками; исходная выгрузка не меняется. Диагностика и предупреждения — в отдельных отчётах, не в карточках Sigur.
- Сотрудники **без ключей включены в общий файл**, даже если во всей базе нет ни одного ключа. Есть отдельный счётчик карточек без карт. Неоднозначные личности по-прежнему перечисляются в исключениях.
- Для обновления примечаний существующих карточек: резервная копия Sigur, проба на копии, обновление только Примечания, без перезаписи карт/сроков.

## Что внутри программы

- Номера карт **включаются в XLS**, а не остаются только в диагностике. Сроки включаются, если соответствующие исходные поля найдены и значения распознаны. Несколько карт — строки продолжения.
- Колонки «Тип пропуска» в XLS нет; Sigur назначает тип «Карта» по умолчанию.
- Поля при импорте сопоставляются **заново по названиям**: «Тип записи» («Сотрудник») — не «Тип пропуска»; последний не сопоставлять.
- Согласованные кадровые поля и фото; формат примечаний — только дата рождения.
- `ДИАГНОСТИКА_СТРУКТУРЫ.json` содержит только структуру и агрегированные количества, без значений персональных данных; позволяет уточнить поля дат.

## Границы

- Статусы и блокировки Болид **не назначаются в Sigur** — права и расписание назначаются отдельно (турникет — общий режим для всех действующих сотрудников, 24/7).
- Нераспознанные коды/даты и неоднозначные люди перечисляются в `Исключения.csv`; при исключениях перенесены не все данные — причина указана для каждой исходной записи.
- Номера карт — вычисленные кандидаты W34 (8 HEX, гипотеза raw08-dallas01-low32, CRC проверена); корректная работа подтверждена эксплуатацией на объекте в v1.0.0.
- Строгий проверочный режим для специалиста: `ИНСТРУКЦИЯ/Проверка_специалиста.py`. Автоматический режим не создаёт фиктивные Approve/ObservedW34.
