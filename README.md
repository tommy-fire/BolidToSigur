# BolidToSigur · v3.4

**Две кнопки: Болид → файл `.bolid` → полный пробный XLS для Sigur.**

1. Распаковать лёгкий ZIP в `C:\BolidToSigur`, открыть `ЗАПУСК.bat`.
2. Ввести логин/пароль → «1. Найти базу и выгрузить». Автопоиск сохранён, `.bak` не используется.
3. «2. Выбрать выгрузку и создать файл Sigur» → выбрать `.bolid`. SQL повторно не нужен.
4. Открыть `ПРОБНЫЙ_ПОЛНЫЙ_Импорт_Sigur.xls` из новой папки результата.

Если `.bolid` уже есть, после обновления достаточно кнопки 2. [Практическая инструкция и сопоставление колонок](01_ПЕРЕНОС.md).

## Что изменено после v3.3

- Номера карт **включаются в XLS**, а не остаются только в диагностике. Сроки включаются, если соответствующие исходные поля найдены и значения распознаны. Несколько карт — строки продолжения.
- Удалена колонка «Тип пропуска» из всех вариантов XLS. Ранее она была пустой у сотрудников без карт; при сопоставлении это могло вызывать ошибку. Без этой колонки руководство Sigur задаёт тип «Карта» по умолчанию. Точная причина ошибки пользователя не воспроизведена: реальный XLS не предоставлен.
- Поля при импорте нужно сопоставить **заново по названиям**. «Тип записи» («Сотрудник») — не «Тип пропуска». Последний не включать в настройках импорта.
- Согласованные кадровые поля и фото сохранены; дата рождения/паспорт/прописка дополнительно дублируются в примечании.
- `ДИАГНОСТИКА_СТРУКТУРЫ.json` содержит только структуру и агрегированные количества, без значений персональных данных; позволяет уточнить поля дат.
- Исправлена опечатка записи «Поле срока» при подготовке проверочной таблицы.

## Честная граница готовности

Это **полный по набору полей пробный импорт**, не подтверждённый рабочий перенос. Номера рассчитаны по поддерживаемой гипотезе CodeP, проходят структуру/CRC и проверки владельцев/коллизий, но **не сверены с реальным считывателем**. Непонятные коды/даты и неоднозначные люди идут в исключения. При исключениях перенесены не все данные.

Статусы и блокировки Болид **не назначаются в Sigur**. Пробный файл включает и неактивных сотрудников/карты. Отсутствие режимов в XLS само по себе не запрещает доступ в существующей базе. Использовать только пустую изолированную тестовую базу без прав; не переключать турникет до сверки. Пустые даты могут дать бессрочность или время импорта — программа показывает их количество, не выдаёт отсутствие данных за успешный перенос.

Строгий проверочный режим для специалиста: `ИНСТРУКЦИЯ/Проверка_специалиста.py`. По умолчанию `safe_w34.build` по-прежнему требует подтверждения карт; `trial_import=True` — отдельный явно пробный путь. Автоматический режим никогда не создаёт фиктивные Approve/ObservedW34 и не наследует их из старой выгрузки.

## Состав и проверки

- `ИНСТРУКЦИЯ/` — программа и инструкция. В полном репозитории запускать `ИНСТРУКЦИЯ/ЗАПУСК.bat`.
- `research/` — официальные руководства и источники.
- `audit/` — тесты и история изменений.
- [Подключение E510](02_ПОДКЛЮЧЕНИЕ.md).

```bash
python -m pip install xlwt xlrd Pillow
python -m unittest discover -s audit -p 'test_*.py' -v
# Linux с Xvfb:
xvfb-run -a python audit/smoke_simple.py
```

49 офлайн-тестов + настоящий Tk GUI с SQL-заглушкой. Реальный SQL, Windows, Sigur и физический проход не испытаны. Результаты: `audit/test_results_v3_4.txt`, `audit/gui_smoke_v3_4.txt`.

Windows/Python 3.10+/Tkinter. Для экспорта БД — pyodbc и Microsoft ODBC-драйвер SQL Server (драйвер отдельно). Для открытия `.bolid` и XLS ODBC не нужен. Персональные выгрузки не хранить в Git; `.bolid` не зашифрован.
