# v3.4 · 30.09.2026

Пользователь сообщил: импортировались организации, «неизвестный тип пропуска», номера и сроки пустые. Уточнил, что база Sigur пустая тестовая. XLS/скрин/версию Sigur не предоставил; точная причина ошибки НЕ установлена.

## Изменения

- По явному запросу полного пробного импорта основной путь теперь `trial_import=True`: кандидаты W34 в XLS как восемь текстовых HEX-знаков; исходные распознанные даты; до пяти карт, строки продолжения без ФИО. Карты не отбрасываются только потому, что даты не найдены. Непустая невалидная дата или инверсия интервала исключает карту, не сотрудника.
- Включены сотрудники без карт; согласованные кадровые поля и фото; примечание сохраняет персональные резервные строки. Без искусственного родительского отдела. Все записи имеют предупреждение о пробном статусе.
- Все XLS больше не имеют «Тип пропуска». Это именно отсутствующая колонка, а не пустое значение. Тип карты по умолчанию документирован руководством. Инструкция требует снять сопоставление этого поля, пересопоставить остальные по названиям; «Тип записи» — самостоятельное поле.
- Метки `hardware_verified`, `source_statuses_verified`, `access_rights_assigned`, `production_ready` всегда False; `trial_cards` вместо «accepted». Код не выдаёт пробные номера за измеренные. Строгий режим по умолчанию сохранён. Операторские Approve/ObservedW34/профили/вручную вписанные даты в автоматическом режиме не наследуются; исходники перечитываются.
- Блокировки не переводятся по неустановленным кодам статуса. Пробный файл намеренно содержит также неактивные записи; инструкция/UI/примечания/отчёт требуют изолированную базу без доступа. Пустые границы явно посчитаны. Назначение режима 24/7 остаётся отдельным этапом после сверки.
- Поддерживаемые имена дат расширены, но являются гипотезами; семантика не объявляется подтверждённой. Несколько подходящих полей → пустая граница + диагностика. Никаких выдуманных дат или извлечения номера из произвольного непонятного кода.
- `ДИАГНОСТИКА_СТРУКТУРЫ.json`: только названия/типы таблиц/полей и количества, без значений строк/ключей/учётных данных. Это следующая требуемая диагностика, если реальные сроки опять отсутствуют.
- Исправлена обнаруженная опечатка: `result[-1]['Поле срока','Начало действия пропуска']` создавала tuple-ключ, который терялся при записи CSV; теперь два отдельных строковых поля.

## Основания совместимости

`research/UserGuide.pdf`: официальное руководство Sigur, редакция 23.09.2026, страницы 143–148. Оригинал: https://sigur.com/doc/SigurUserGuide.pdf
- p143: текстовые ячейки, W34 = 4 байта / 8 HEX; при отсутствии поля «Тип пропуска» всем пропускам присваивается «Карта».
- p144: до 5 пропусков, строки продолжения; начало/конец действия пропуска с временем. Формулировка про даты продолжения неоднозначна — проверять фактически в установленной версии.
- p147–148: ручное сопоставление по столбцам, права оператора, конфликтное обновление по «Тип записи»/ФИО/отделу.
Новое свойство типа добавлено в 1.6.7.60: https://sigur.com/news/events_211125/ . Пользовательскую версию мы пока не знаем.

## Результат тестов

49 тестов (39 прежних, 10 новых), Linux/Tk/Xvfb оба интерфейса. Новые: полный набор+фото+ведущие нули+даты/время; отсутствие типа пропуска; сотрудники без карт; неизвестные и неоднозначные даты; несколько карт; неподдержанный CodeP; коллизии/переполнение; неактивный статус с предупреждением; отсутствие фиктивных подтверждений; отсутствие персональных значений в структурной диагностике; исходная .bolid неизменна; второй шаг не использует SQL.

Результат не доказывает работу в реальном Sigur/Windows, на SQL пользователя или на считывателе. Причина «перенеслись только организации» без реального файла и протокола импорта ещё не воспроизведена.
