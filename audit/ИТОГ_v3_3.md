# v3.3 · 30.09.2026

Основной UI: логин/пароль и ровно две кнопки. Автопоиск+экспорт сохраняет .bolid рядом с программой; открытие+подготовка сохраняет результат туда же. Никаких вкладок, галочек или выбора полей в основном окне. Неоднозначный выбор базы остаётся обязательным, если обнаружено несколько баз.

Неполное выполнение бизнес-цели явно обозначено: полностью автоматического рабочего импорта карт нет. Нет реальной схемы статусов и контрольных считываний. Отсутствие колонки прав в XLS не доказывает запрет прохода после ошибочного импорта в действующую базу. Поэтому основной XLS не содержит назначений карт. Диагностические номера только в отдельном CSV с префиксом НЕПОДТВЕРЖДЁН:, оригиналами и сведениями о неподтверждённой гипотезе формата. Первая сверка и проверка прав/сроков на объекте остаётся необходимой.

Старый проверочный режим перенесён в Проверка_специалиста.py без потери возможностей. Метод build по умолчанию сохраняет прежние строгие ограничения. Флаг candidate_draft не подменяет Approve/ObservedW34, не выдаёт пропуска в XLS, не сохраняет в отчёт ложную калибровку. Кандидаты строятся из исходного CodeP, предыдущие операторские решения из .bolid в простом режиме не принимаются как подтверждение. Точные имена полей дат используются только как диагностическое предположение; несколько/пустые границы не угадываются.

Оригинальный файл не меняется; рабочая копия новая. Все исходные ключи сохранены, неоднозначные люди/карты имеют причины исключения. Кадровый XLS включает неактивных людей (статусы неизвестны), требует изолированной тестовой базы без прав; это не «производственно безопасный» файл по одному названию. Тестовый родительский отдел и предупреждения не являются механизмом блокировки.

39 офлайн-тестов проходят. Новый тест реального Tk под Linux/Xvfb проверяет ровно две кнопки, отсутствие вкладок/галочек, весь цикл с SQL-заглушкой, сохранение около программы. Проверочный интерфейс также повторно протестирован. Ни Windows, ни настоящая БД, ни Sigur, ни считыватели не проверены.
