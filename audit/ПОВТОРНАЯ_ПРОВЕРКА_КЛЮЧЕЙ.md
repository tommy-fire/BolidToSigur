# Повторная проверка ключей — 29.09.2026

## Итог

Перенос технически реализован для проверяемых групп ключей. Возможность автоматического переноса всей конкретной базы пока не установлена: нет реальных записей CodeP и номеров тех же карт, считанных новым оборудованием.

21 офлайн-тест проходит. Дополнительно проверены эталон CRC8/MAXIM `123456789 → A1`, 2000 воспроизводимых случайных шестибайтовых серийных номеров, отклонение всех 64 одиночных битовых повреждений одной записи, коллизия разных 48-битных серийных номеров при одинаковых младших 32 битах, отклонение дубликата карты с разными сроками. Это проверка реализации, не доказательство соответствия считывателям объекта.

## Что обязательно проверить на объекте

1. Выгрузить существующую базу через автопоиск. Посчитать распознанные и неизвестные форматы, не утверждать процент заранее.
2. Разделить карты на однородные группы по происхождению/типу и прежнему способу регистрации. Отдельно учитывать старшие два байта серийного номера. Название профиля задаёт оператор: программа не может узнать физический тип карты из одного CodeP.
3. На каждую такую группу получить минимум три разных номера реальных карт в Sigur; хотя бы один номер должен отличаться при обращении порядка байтов. Проверить каждую используемую группу старших байтов, а не только один общий набор из трёх карт. Не вводить кандидаты программы вместо реальных считываний.
4. Проверить эти карты на каждом из четырёх новых считывателей. Одинаковая надпись W34 не доказывает одинаковую настройку. Любое расхождение останавливает соответствующий профиль до выяснения причин.
5. Импортировать 3–10 сотрудников в пустую тестовую базу. Проверить имя владельца в журнале событий, ведущие нули номера, фото, сроки и явно назначенные права. Проверить отказ запрещённой/невыданной карте и отказ обычному сотруднику в комнату охраны.
6. После успешной проверки решить, какие группы переносить автоматически, какие карты перечитать индивидуально. При массовом переносе повторить сверку количеств и владельцев, не включать все права по умолчанию.

## Неустранимые одним алгоритмом ограничения

- Из шестибайтового внутреннего серийного номера берётся кандидат в четыре байта. CRC проверяет внутреннюю запись, но не подтверждает, что новый считыватель выдаёт именно эти четыре байта.
- Два разных исходных ключа могут дать один номер W34. Такие известные коллизии отклоняются, включая конфликты с неразрешёнными записями.
- Для нераспознанного ключа неизвестен номер на новом считывателе. Поэтому полную проверку его коллизий автоматически провести нельзя. Само исключение записи из импорта **не гарантирует отказ физической карте**, если её реальный номер совпадёт с импортированным. Подозрительные и запрещённые карты проверять отдельно; при совпадении не выдавать этот номер, а менять идентификатор/способ чтения.
- Пустая целевая база убирает конфликт с ранее выданными в Sigur картами, но не устраняет физические совпадения номеров и возможность клонирования карты.
- Нераспознанную карту можно перенести по индивидуально считанному номеру после проверки владельца. Если требуемый идентификатор не передаётся новым оборудованием, нужны изменение конфигурации или замена карты — не подбор среза HEX вслепую.
- Статусы, права, расписания и начало действия не переносятся как действующие ограничения автоматически. Их необходимо настроить и проверить в Sigur.

Таким образом, рабочий путь есть; гарантировать перенос всех ключей без индивидуального считывания до пилотной проверки нельзя.
