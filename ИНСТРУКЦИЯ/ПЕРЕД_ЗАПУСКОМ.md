# Болид → Sigur · простой запуск v3.3

1. Создай папку **`C:\BolidToSigur`**.
2. Распакуй **содержимое архива программы прямо туда**. Не запускай из ZIP.
3. Открой **`ЗАПУСК.bat`**.
4. Введи логин и пароль SQL. Нажми **«1. Найти базу и выгрузить»**. Для Windows-входа логин пустой.
5. Рядом с программой появится **`Болид_дата.bolid`** — единый файл с сотрудниками, исходными картами, справочниками и доступными фото.
6. Нажми **«2. Выбрать выгрузку и создать файл Sigur»**, выбери этот `.bolid`.
7. Результат появится рядом, в папке **`Для_Sigur_дата`**. На Windows программа откроет её сама.

**Нет вкладок, профилей, галочек и выбора полей дат.** Если найдены несколько баз, программа попросит выбрать рабочую — угадывать её нельзя. Вторая кнопка работает без подключения к Болид. Повторные запуски не перезаписывают прежние выгрузки.

## Важное ограничение текущей версии

**Полностью автоматический рабочий перенос карт пока НЕ подтверждён.** Реальных пар «код Болид → номер той же карты от нового считывателя» и проверенной схемы статусов нет. Не выдаём кандидаты за проверенные пропуска.

Поэтому результат сейчас такой:
- **`Для_Sigur_СОТРУДНИКИ_БЕЗ_КАРТ.xls`** — согласованные кадровые данные и фото, **без назначений карт**. Для теста сотрудники помещаются в отдел «ТЕСТ — НЕ НАЗНАЧАТЬ ДОСТУП». Само название отдела не блокирует доступ; права ему не назначать.
- **`КАРТЫ_ТОЛЬКО_СВЕРКА_НЕ_ИМПОРТ.csv`** — неподтверждённые кандидаты W34 с исходными кодами, владельцами и предположенными датами. Это не файл выдачи пропусков.
- **`Данные_всех_ключей.csv`** — все исходные записи ключей, в том числе заблокированные/непонятные. Они не удаляются.
- **`Исключения.csv`**, предупреждения и **`СНАЧАЛА_ПРОЧИТАТЬ.txt`** — что не распознано и почему. Неоднозначные сотрудники идут отдельно; если однозначных нет, XLS не создаётся.

**Это отличается от готового переноса «выгрузил — все сразу проходят».** До такого результата нужно один раз сверить реальные карты, назначение полей начала/окончания и статусов. Интерфейс упрощён, но неизвестные данные не стали подтверждёнными. Для специалиста сохранён прежний проверочный режим, основной запуск его не показывает.

Кадровый файл включает и неактивных сотрудников: статусы Болид не интерпретируются автоматически. Только пустая изолированная тестовая база Sigur, без назначения доступа. Импорт: Персонал → Импорт из Excel → сопоставление полей. Фото держать рядом с XLS. Не импортировать подряд в рабочую базу: дубли и обновление не проверены.

Дата рождения, паспорт и прописка идут отдельными колонками; примечание сохраняет резервные строки в согласованном порядке. Неизвестные форматы примечаний требуют сверки. Телефон/email и произвольные дополнительные поля не входят в XLS.

Даты в диагностике выбираются по точным именам известных полей. Если полей несколько, поле не выбрано; пустые границы и точное время не угадываются. Смысл найденных полей ещё нужно проверить. Исходные значения остаются в выгрузке. Несколько карт со сроками требуют отдельного теста.

## Установка один раз

Windows, **Python 3.10+ с Tkinter**. Если прежняя программа запускалась, Python обычно уже есть. Запускатель устанавливает Python-библиотеки при необходимости (нужен интернет). Для первой кнопки нужен Microsoft ODBC-драйвер SQL Server; pip его не устанавливает. Для второй кнопки ODBC не нужен. Если папка недоступна для записи, перенеси её из Program Files в обычную папку на C.

`.bolid` — контейнер программы, не `.bak`, не SQL-база для восстановления и не файл для прямого импорта в Sigur. Он **не зашифрован**; содержит персональные данные и номера карт. Храни защищённо. В `Служебные` остаются исходники и рабочие копии для разбора ошибок. SQL только читается.

Согласованная рабочая схема на будущее: **турникет — всем действующим сотрудникам, вход/выход 24/7; комната охраны отдельно**. Права программа не назначает. Сроки и блокировки не должны исчезнуть при переключении. До проверки не отключать Болид и не ограничивать аварийный выход.
