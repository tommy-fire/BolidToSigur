# Перенос Болид → Sigur · v3.1

## Что скачать и запустить

Скачай весь архив **ветки `fix/safe-w34-migration`**, распакуй в новую папку. Запуск: **`ИНСТРУКЦИЯ/START_SAFE.bat`**. Для работы достаточно папки ИНСТРУКЦИЯ целиком; эта памятка также скопирована внутрь неё.

Нужны Windows, Python 3.10+ с Tkinter и Microsoft ODBC-драйвер SQL Server. Если Python уже работал — переустанавливать не нужно. BAT установит недостающие Python-библиотеки (нужен интернет). ODBC-драйвер устанавливается отдельно, pip его не заменяет.

## 1. Найти базу и выгрузить

Введи логин/пароль → **НАЙТИ БАЗУ**. Сервер можно оставить пустым: используется прежний автопоиск. Для Windows-входа логин пустой. Выбери рабочую базу → **ВЫГРУЗИТЬ**. Если поменял учётные данные, повтори поиск.

Работаем с существующей базой, только SELECT. Восстановления из `.bak` нет. Штатные резервные копии обеих систем перед переключением всё равно нужны для сохранности.

В новой папке `snapshot_…` сохраняются pList.csv, pMark.csv, доступные справочники, schema.json, фотографии, Персонал.json, Предупреждения_данных.csv и Проверка.csv. Все исходные поля сотрудников и ключей остаются для сверки, даже если не входят в импорт. COMPLETE.txt означает завершение основных чтений, не завершение импорта. Таблицы читаются последовательно, не в единой транзакции: на время чтения не меняй сотрудников/карты в Орионе.

Непонятное фото даёт предупреждение, а не останавливает всю выгрузку. Сетевые UNC-пути автоматически не открываются. Неразрешённые названия организаций/отделов/должностей требуют сверки. Не заменяй их произвольными ID.

## 2. Согласованный состав

- ФИО, табельный номер.
- Компания/подразделение → «Отдел». Sigur трактует запятую как вложенность: `Компания, Подразделение`. Если в самом названии есть запятая, перед импортом проверь структуру отдельно.
- Должность и фото.
- Дата рождения, паспорт РФ (включая распознанные реквизиты выдачи), прописка.
- Проверенные карты W34.
- Начало и окончание действия **каждой карты**, включая точное время.

Телефон, email и произвольные дополнительные поля не добавляются в целевой XLS. «Орион ID» — служебная колонка сверки, а не команда назначить ID в Sigur.

### Дата рождения, паспорт и прописка

По умолчанию готовятся три дополнительные колонки. В Sigur создай дополнительные параметры: «Дата рождения» типа «Дата», «Паспорт РФ» и «Прописка» типа «Строка» и сопоставь их при импорте.

Программа читает поддерживаемые отдельные поля Болид, а также строки примечания с подписями `Дата рождения:`, `Паспорт РФ:`, `Прописка:`. Неподписанные даты, неизвестный формат и конфликты **не угадываются**; смотри предупреждения и исходный текст. Если ваша запись устроена иначе, потребуется подстроить разбор по обезличенному примеру. Пустое дополнительное поле при конфликте не означает отсутствие сведений в Болид.

Если импорт дополнительных полей не настроен, включи галочку **«Дата рождения / паспорт / прописка — в Примечание вместо отдельных полей»**. Первые строки будут:

```text
Дата рождения: …
Паспорт РФ: …
Прописка: …
```

Ниже сохраняется исходное примечание для сверки. В этом режиме отдельные три колонки не создаются. В обычном режиме они создаются, а «Примечание» остаётся пустым — дублирования нет. Ошибки извлечения нужно разрешить до массового импорта; повторная выгрузка/обработка не исправляет неизвестный формат автоматически.

## 3. Проверить W34 — прежде чем разрешать перенос

1. Получи номер физической карты через новый считыватель в Sigur: **8 HEX-знаков**, включая нули. Не используй напечатанный на пластике номер или кандидата программы вместо реального считывания.
2. Найди именно эту карту и владельца в Болид. При нескольких картах одного человека одного ФИО недостаточно.
3. В окне выбери строку → «Номер из Sigur» → «Сохранить номер».
4. Повтори минимум для трёх разных карт одной однородной группы. Хотя бы один номер должен различаться при обращении порядка байтов. Проверь разные встречающиеся старшие байты внутреннего серийного номера.
5. Назначь контрольным и остальным картам этой же подтверждённой группы одинаковый профиль. Не смешивай неизвестные технологии/способы чтения.
6. Повтори проверку реальных номеров на всех четырёх считывателях.

Кандидат W34 — гипотеза. CRC внутреннего кода не доказывает соответствие новому считывателю. Неизвестные FE-последовательности не обрезаются наугад. Несовпадение контрольного номера останавливает весь профиль. Отличающиеся старшие байты требуют новой сверки. Для неизвестного формата возможен индивидуально считанный номер с пустым профилем.

Коллизии известных номеров разных владельцев отклоняются, включая не одобренные записи. Для нераспознанной карты номер неизвестен: исключение её записи **не гарантирует отказ физической карте**, если она выдаёт тот же номер, что разрешённая. Проверяй запрещённые и подозрительные карты отдельно.

Выдели нужные строки → **«Разрешить выделенные»** только после проверки владельца, статуса, актуальности сотрудника и сроков в Болид. Не разрешай всё вслепую. Уволенные/заблокированные карты не активируются автоматически. Программа не угадывает смысл служебных статусов.

## 4. Выбрать начало и окончание

Внизу окна два списка исходных полей ключа:
- поле **начала действия**;
- поле **окончания действия**.

Выбери их после сверки с АБД Болид. Нельзя выбрать одно поле для обеих границ. Не выбирай дату создания записи вместо начала действия.

В XLS выходят актуальные колонки **«Начало действия пропуска»** и **«Окончание действия пропуска»**, формат `ДД.ММ.ГГГГ ЧЧ:ММ:СС`. Если в исходнике только дата, время будет 00:00:00, не конец дня. Неизвестный формат, часовой пояс и доли секунды требуют отдельного решения: они не округляются незаметно. Начало должно быть раньше окончания. Уже прошедшая дата начала сохраняется.

Если выбранное поле пусто, ограничение не придумано за вас. Без импортируемого начала Sigur может поставить время импорта, без окончания — бессрочность. **Перед выдачей прав проверь обе границы каждой карты!** Не подменять эти поля параметрами «Начало доступа»/«Окончание доступа» всего сотрудника.

Для индивидуальной корректировки в Проверка.csv существуют «Начало действия пропуска» и старое внутреннее имя «Срок действия» (это окончание). Они имеют приоритет над выбранными полями. После внешнего редактирования заново открой Проверка.csv в программе, иначе сохранение окна перезапишет изменения. Исходные ID, владельца, RawCodeP и Format менять нельзя.

### Если у сотрудника несколько карт со сроками

В официальном руководстве от 23.09.2026, стр. 144, новые поля дат перечислены, но описание строк продолжения по-прежнему называет только старый «Срок действия». Поэтому без реального теста нельзя гарантировать применение обеих дат ко второй и последующим картам.

**По умолчанию все карты такого человека исключаются с явной причиной.** Это не потеря данных. Они остаются в исходниках, Исключения.csv и Сверка_каждой_карты.csv.

Для отдельного испытания есть галочка **«ДИАГНОСТИКА: разрешить несколько карт со сроками»**. Она создаёт файл **ДИАГНОСТИКА_НЕ_ДЛЯ_РАБОТЫ.xls**, не снимает проверки W34/владельцев/коллизий и не предназначена для рабочей базы. Сроки записываются в новые колонки, старой колонки «Срок действия» в XLS нет.

Опасность: дополнительные карты могут получить бессрочность или даты первой карты. В пустой тестовой базе проверь владельца и обе границы каждой карты, особенно дополнительные; испытай разные периоды, будущее начало и уже прошедшее окончание. Проверяй карточку конкретного пропуска, а не только сотрудника. Диагностический файл не импортировать поверх основного: для него отдельная пустая база либо восстановление чистого состояния. До проверки права не назначать. Если Sigur не применяет даты правильно — массовый перенос таких людей остановить; настроим отдельный подтверждённый путь.

## 5. Создать файлы и проверить отчёт

- **Сотрудники_без_ключей.xls** — все однозначные кадровые карточки без назначений карт, в том числе люди без карт. Исключения по неоднозначным ФИО/табельным номерам — отдельным CSV.
- **ТЕСТ_Импорт_Sigur.xls** — разрешённые и проверенные карты с сотрудниками; при отсутствии принятых карт не создаётся. При включённой диагностике вместо него — файл с предупреждением в имени.
- **Фотографии/** — держать рядом с XLS при переносе на другой ПК.
- **Принятые.csv / Исключения.csv** — решения по всем исходным ключам. Принятые + исключённые = исходное количество.
- **Сверка_каждой_карты.csv** — владельцы, номера, обе даты, причины исключений и пустые графы для отметок проверки в Sigur. Номера в исключённых строках не подтверждены для импорта.
- **Данные_всех_ключей.csv** — полные исходные записи ключей.
- **Предупреждения_данных.csv** — фото, справочники, разбор примечаний.
- **Отчёт.json** — количества, профили, выбранные поля сроков, режим кадровых полей. Только `complete: true` означает, что файлы сформированы полностью; это не подтверждение импорта.

Не импортируй оба кадровых XLS подряд без понимания обновления: возможны дубли. Первое испытание — файл с картами, 3–10 сотрудников. Пакет рассчитан на **пустую тестовую базу** и не сверяет карты с существующей рабочей базой Sigur. До объединения с ней нужна отдельная сверка.

## 6. Импорт и права

В Sigur: **Персонал → Импорт из Excel** → сопоставь колонки. Используется настоящий `.xls` с текстовыми ячейками. Не переименовывай XLSX в XLS.

Проверь фото, ФИО, табельный номер, отдел/должность, кадровые поля, каждую карту и обе даты. Сроки карты должны ограничивать доступ, а не просто отображаться текстом.

**Согласованный общий режим: «Турникет — 24/7»** — вход и выход, все дни недели круглосуточно. Создаётся и назначается в Sigur отдельно, после проверки. Доступ к комнате охраны **не включать**: настроим позже. Общий режим не отменяет начало/окончание карты и блокировки.

Перед переключением проверь:
- разрешённая карта открывает турникет, журнал показывает правильного сотрудника;
- заблокированная/просроченная карта не открывает;
- карта с будущим началом не открывает раньше срока;
- обычный сотрудник не получает доступ в комнату охраны;
- аварийный выход работает независимо от переноса данных.

Болид не удалять и не отключать до успешной приёмки. Не закрывать эвакуационный выход ради испытаний.

## Что уже проверено

Офлайн проверены преобразование поддерживаемого CodeP, CRC, нули, коллизии, фото/справочники, кадровый состав, примечания, обе даты и содержимое XLS. Реальный SQL пользователя, GUI под Windows, импорт установленной версии Sigur и проходы на объекте **не проверены**. Неизвестные названия полей/форматы заметок могут потребовать корректировки по первой выгрузке.

Официальная основа: https://sigur.com/doc/SigurUserGuide.pdf, редакция 23.09.2026, стр. 143–147. Копия в research/UserGuide.pdf. Последняя версия ПО сама по себе не подтверждает соответствие номеров старых карт новому оборудованию.
