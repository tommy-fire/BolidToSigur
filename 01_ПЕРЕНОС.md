# Перенос Болид → Sigur: короткая инструкция v3

## 1. Запуск — как раньше

Распакуй весь архив в новую папку. Открой **`ИНСТРУКЦИЯ/START_SAFE.bat`**. Старые запускатели «Запустить_выгрузку_из_Болид» и «Запустить_миграцию» открывают то же окно.

Нужны Windows, Python 3.10+ с Tkinter и Microsoft ODBC-драйвер SQL Server. Если Python уже стоял и прежняя программа запускалась — переустанавливать его не нужно. Запускатель при необходимости установит Python-библиотеки pyodbc, xlwt и Pillow (для установки нужен интернет). Если не установлен именно ODBC-драйвер, pip его не заменит.

## 2. Введи логин и пароль → НАЙТИ БАЗУ

- Сервер можно оставить пустым — работает прежний поиск служб SQL, реестра и вариантов подключения.
- Если используешь Windows-вход, логин оставь пустым.
- После поиска выбери рабочую базу из списка. При одной найденной базе она подставляется автоматически, но перед выгрузкой программа всё равно просит подтверждение.
- Если несколько баз — не выбирай просто самую большую. Сверь с настройками работающего Ориона.
- Изменил логин/пароль после поиска — повтори поиск, чтобы не использовать прежние учётные данные.
- Пароль не сохраняется в результатах. Никому его не отправляй.

**Восстановления `.bak` в программе больше нет.** Работаем только с существующей доступной базой, как раньше. Штатные резервные копии Болид и Sigur перед переключением по-прежнему нужны как мера сохранности — не как входные файлы нашей программы.

## 3. Нажми ВЫГРУЗИТЬ

Программа только читает базу. Сохраняет в новую папку `snapshot_…`:

| Файл | Содержимое |
|---|---|
| pList.csv | Все выгруженные поля сотрудников |
| pMark.csv | Все записи ключей, включая без найденного владельца; исходные CodeP, CodePAdd, статусы и сроки |
| Справочники CSV | Найденные справочники организаций, подразделений и должностей |
| schema.json | Имена/типы полей, количества строк |
| COMPLETE.txt | Основные чтения завершены; это не признак завершённого импорта |
| Фотографии/ | Распознанные фотографии, имена привязаны к исходному ID, а не только к ФИО |
| Персонал.json | Подготовленные кадровые поля |
| Предупреждения_данных.csv | Проблемы фото и неразрешённые ID справочников |
| Проверка.csv | По одной строке на исходный ключ; программа показывает её в окне |

Двоичные поля исходных таблиц сохраняются в HEX, NULL — пустой ячейкой; это диагностический экспорт, не замена резервной копии SQL. Не редактируй исходные pList/pMark/schema: они нужны для контроля связей.

Выгрузка нескольких таблиц — отдельные SELECT, не единый снимок транзакции. На время операции желательно не менять сотрудников/карты в Орионе. Ошибки чтения ключевых таблиц останавливают операцию; ошибочная фотография попадает в предупреждения и не останавливает остальные данные.

При закрытии программы можно продолжить позднее: **«Открыть прежнюю выгрузку» → Проверка.csv**. Если основное чтение закончено, но подготовка кадровых данных упала, не считай такой результат готовым: пришли текст ошибки, сохрани исходную папку.

## 4. Сверь номера W34 в окне программы

Нужен хотя бы один правильно подключённый считыватель E510. Для проверки номера замок и турникет уже подключать не обязательно.

1. Возьми карту с известным владельцем. Получи её номер в Sigur в режиме считывания/выдачи пропуска. Убедись, что используется W34 — 4 байта, **8 HEX-знаков**, включая ведущие нули. Не путай с напечатанным на пластике номером.
2. Найди именно её ключ в АБД Болид и соответствующую строку в программе. Если у человека несколько карт — одного ФИО недостаточно.
3. Выдели одну строку, введи номер в **«Номер из Sigur»**, нажми **«Сохранить номер»**.
4. Повтори для минимум **трёх разных номеров одной однородной группы** (одинаковый прежний и новый способ чтения). Желательно разные значения, включая нули/FE, если доступны.
5. Укажи название профиля, например «Основные карты». Выдели контрольные строки и остальные карты **этой же подтверждённой группы**, нажми **«Задать выделенным»**.

Автоматическое преобразование применяется только если контрольные номера совпали. Несовпадение блокирует профиль. Отличающиеся от контрольных старшие байты внутреннего кода требуют дополнительной индивидуальной сверки. Не объединяй неизвестные типы карт в одну группу лишь ради прохождения проверки.

Для карты, которую алгоритм не разобрал, можно оставить профиль пустым и сохранить её индивидуально считанный номер. Это не означает, что нужно собирать все карты: сначала выясняем долю распознанных и сверяем группы.

**«Кандидат W34» не означает «правильный номер».** Корректная CRC внутреннего кода Болид не доказывает совпадение с выходом нового считывателя. Три совпадения — минимальная практическая проверка, не универсальная гарантия для смешанной базы. Проверь также номера на остальных трёх считывателях.

## 5. Выбери действующие ключи

Ctrl/Shift — выделение нескольких строк. Ctrl+A — все строки.

Нажми **«Разрешить выделенные»** только после проверки:
- правильного владельца;
- актуальности сотрудника;
- блокировки/активности ключа в Орионе;
- начального и конечного срока;
- необходимости переноса этой карты.

Кнопка **«Исключить выделенные»** снимает разрешение. Это ничего не меняет в базе Болид.

**Не разрешай все записи вслепую.** Исходные служебные статусы сохраняются, но их смысл не угадывается. Заблокированные, уволенные, неподтверждённые записи оставь исключёнными. Новая карточка Sigur не наследует запреты Болид сама собой.

## 6. Сроки и дополнительные данные

Внизу окна есть список полей **«Поле окончания срока ключа»**. Выбери поле только после проверки по АБД Болид. Произвольную дату рождения/выдачи документа программа больше не выбирает как срок.

- Если выбрано поле, срок подставляется из исходной записи ключа.
- Индивидуальный срок из «Срок действия» в Проверка.csv имеет приоритет; при необходимости поправим его отдельно.
- Без выбранного поля и без индивидуального срока ячейка остаётся пустой. Это **не сохранение ограничения**: в Sigur пустой срок может означать бессрочность.
- Если значение содержит ненулевое время/часовой пояс, автоматический перенос этой карты останавливается: не округляем время незаметно. Нужна отдельная настройка.
- Начало действия, расписание и права доступа автоматически не назначаются; исходные значения остаются в файлах. Карты с будущим началом/особым расписанием не выдавай в работу до настройки ограничений.

**Что готовится автоматически:** ФИО, табельный номер, телефон, отдел/должность по найденным справочникам, фотографии; дата рождения — в «Примечание», адрес/паспорт/email и остальные поддерживаемые текстовые кадровые поля — отдельными колонками. Исходные ID организаций/отделов/должностей также сохраняются для сверки.

Непонятные числовые ID не подставляются вместо названий. Смотри Предупреждения_данных.csv. Технические/двоичные поля сохраняются в исходниках, но не объявляются обычными импортируемыми полями. UNC-фото по сетевым путям автоматически не читаются; такие фото потребуют локального копирования/настройки.

## 7. СОЗДАТЬ ФАЙЛЫ

Результат в новой папке `result_…`:

- **Сотрудники_без_ключей.xls** — кадровые карточки, фото и дополнительные поля **всех однозначно определённых сотрудников**, включая тех, у кого нет карт. Исключения по пустым ФИО, совпадающим ФИО/отделу или табельному номеру — в одноимённом CSV.
- **ТЕСТ_Импорт_Sigur.xls** — кадровые карточки с прошедшими проверку и разрешёнными ключами. Если ни одна карта не прошла — этого файла нет.
- **Фотографии/** — фото для обоих файлов. Не отделять от таблиц при переносе на другой ПК.
- **Принятые.csv / Исключения.csv** — каждый ключ и причина решения; суммы должны совпадать с исходным количеством.
- **Данные_всех_ключей.csv** — исходные поля ключей, в том числе статусы/параметры, которые не назначаются автоматически в Sigur.
- **Предупреждения_данных.csv** — фото и справочники.
- **Отчёт.json** — количества, контрольные профили, фото, исключения; `complete: true` означает, что формирование файлов закончено. Это не подтверждение импорта в Sigur.

Больше пяти разрешённых карт у одного человека — его карты исключаются до явного выбора нужных. Повторы, номера у разных людей (включая не одобренные ключи), неоднозначные владельцы не пропускаются незаметно.

**Не импортируй оба XLS подряд в новую базу без понимания режима обновления.** Для первого теста достаточно файла с ключами. Файл «без ключей» нужен для независимого переноса кадров и оставшихся сотрудников. Этот пакет предназначен для **пустой тестовой базы**. Если в целевой базе уже есть карточки, сначала нужна отдельная сверка их номеров и владельцев — текущий инструмент такой выгрузки Sigur не получает. Не использовать его для обновления существующей рабочей базы без этой сверки.

XLS выбран специально: официальный импорт персонала Sigur требует текстовые ячейки и формат `.xls`; XLSX нельзя просто переименовать. Ограничение до пяти пропусков также описано в руководстве производителя. [2](https://sigur.com/features/sync_employee_data/)

## 8. Импорт — сначала 3–10 человек

1. Сделай резервную копию Sigur. Для этого пакета используй отдельную **пустую тестовую базу**, чтобы исключить коллизии с ранее выданными картами.
2. Персонал → Импорт из Excel → выбери файл с ключами.
3. Свяжи стандартные колонки: ФИО, отдел, должность, номер/тип пропуска, срок, табельный номер, телефон, фото, примечание. Не назначай автоматически «доступ везде».
4. Для паспортных/адресных и прочих дополнительных колонок создай соответствующие дополнительные поля Sigur и сопоставь их в импорте. «Орион Status» — справочное значение, **не автоматическая команда блокировки**.
5. Создай отдельные режимы: «Турникет» для разрешённых сотрудников и «Комната охраны» только для охраны/уполномоченных.
6. Проверь ФИО, фото, номер, сроки, права и все четыре считывателя. В журнале должно появиться **правильное имя сотрудника**, а не просто «проход разрешён». Проверь запрещённую карту и отказ обычному сотруднику в комнату охраны.
7. Только после успешного теста переноси остальное. Болид до завершения приёмки не удаляй.

## Что прислать, если не получилось

Скрин ошибки, на какой кнопке она появилась, версии Ориона и Sigur. Для анализа схемы — schema.json после проверки содержимого. Не присылай пароль, полную базу, фотографии и паспортные данные без необходимости. Для проверки алгоритма нужны точные пары кодов тестовых/деактивированных карт без ФИО; нельзя произвольно менять цифры, иначе проверка CRC потеряет смысл.

## Что проверено разработчиком

Автопоиск использует прежние функции подключения. Офлайн-тесты проверяют выбор рабочей аутентификации и закрытие соединения, строгий разбор W34, запреты, фото/допполя/сроки и реальную запись/чтение XLS. **Ни подключение к вашему SQL Server, ни импорт в установленный Sigur, ни GUI под Windows пока не испытаны.** Поэтому это исправленная версия для проверки на объекте, не обещание готового массового переноса.
